# Medical-officer access → Medbay terminal (RE-03)

One isolated container provides the **owned medical-officer access-control challenge** and its authenticated handoff into Medbay RE-03 aboard **Erebus**, operated by Tallis Group. The temporary standalone `crew` foothold is not a decision about the campaign's `station_crew` versus `controlsvc` identity. The unified campaign still needs an agreed cross-service identity/session interface; this service does not pretend that is already wired.

## Start / reset / test

From the repository root:

```bash
docker compose -p medbay-standalone -f containers/operations/services/medbay/compose.yml up -d --build
curl -fsS http://127.0.0.1:18082/health
python3 containers/operations/services/medbay/tests/test_medbay.py
python3 containers/operations/services/medbay/tests/test_live.py
# Reset this standalone container only (does not touch other Operations routes):
bash containers/operations/services/medbay/scripts/reset.sh
```

Open `http://127.0.0.1:18082/` on the Docker host. Only the host's loopback interface is published. For native development without Docker, run `bash containers/operations/services/medbay/scripts/build.sh` followed by `python3 containers/operations/services/medbay/app.py`; the default native port is 8080 on loopback. The generated ELF is host-architecture specific and ignored by Git; the Docker build generates the correct ELF for its image architecture. Reset restarts ephemeral sessions, recovery code and export credential on the next start.

Medical officer **Yara Nassar (`y.nassar`)** has an emergency-recovery grant; her terminal holds an ORACLE audit selector from the blackout. Discover the officer handoff, obtain the ELF from the officer-only terminal, and trace its *live execution path* rather than trusting a visible decoy. Submit the authentic audit reference to open the dispensing ledger, clinical notes and Chronicle. Establish researcher **Wu Yan's last verified status and sighting time**, without treating this as proof of his ultimate fate. A recovered configuration credential also works against a simulated station failsafe configuration interface; determine the permitted local instruction to collect the separate hard flag. This simulation cannot operate real equipment.

For binary analysis: `file`, `strings`, `objdump -d`, `readelf` or a debugger work. The server exposes `GET /api/medbay/artifact` to an authenticated medical officer; `./artifact3_binary --verify <audit-reference>` checks your hypothesis. This native tool requires a compatible Linux architecture; use a matching host or inspect/run it inside the image. The browser terminal exposes the interactive account, audit, case and failsafe steps.

## Integration interface (standalone today, campaign adapter pending)

The browser and JSON API share a same-origin `medbay_session` HttpOnly cookie. `POST /api/login` accepts `{username,password}` and issues that cookie; `GET /api/me` reports `crew` or `medical-officer`. Standalone crew access is a local demo fixture, not a credential issued by another service. `GET /api/access/grants` lists the caller's routine grant; `GET /api/access/grants/{id}` intentionally fails to enforce object ownership. `POST /api/access/recover` accepts `{recovery_code,new_password}` (8–128 characters), consumes the grant's code once, and returns a status without exposing the new password. The caller must then log in as `y.nassar`; a successful officer session can call `GET /api/medbay` and `GET /api/medbay/artifact`, followed by the existing RE-03 reconciliation endpoint. Neither a grant read nor a recovery response directly upgrades a crew cookie.

**Campaign handoff proposal, not implemented:** after the team agrees on a foothold identity, map its authenticated user to this daemon's crew principal through a reviewed trust boundary, or proxy the officer session into this service. Do not accept an unverified request header as identity. Preserve the officer-only endpoint checks and the one-time recovery semantics; decide cookie scope, expiry, session revocation, service ownership and reset coordination with the Gateway/Security owners before wiring `infra/compose.yml`. This independent stage has no assessed manifest ID/receipt of its own; RE-03 retains `THREAD_03`.

## Implementation/assessor contract

- **Owned medical-officer access stage (unassessed handoff; no new manifest ID):** sign in as routine crew, list your visible grant, then enumerate the next sequential ID. The Access Control Daemon exposes Yara's emergency grant to any authenticated user without an object-owner check (IDOR). The leaked bearer recovery code permits a single reset of `y.nassar`; a fresh officer login is the required handoff into `GET /api/medbay` and the RE-03 artifact. Guest and ordinary crew sessions cannot reach officer material. The recovery code is consumed atomically; repeated reset requests fail and a process reset rotates the code and unknown initial officer password. No proposed roster password is baked in or accepted. Mitigation: enforce grant ownership before returning recovery material and verify account-holder authority at reset, not just possession of a bearer code.
- **RE-03:** the artifact contains three masked audit references and selects one through `route()`. The player traces control/data flow and submits the genuine reference to `/api/medbay/reconcile`; a decoy fails. The native tool still emits the existing `THREAD_03` receipt for compatibility with the separate completion checker. Mitigation: authenticate the audit provenance server-side rather than using a client-visible selector as truth.
- **Mid-flag:** supported conclusion is checked server-side only after medical-officer access and successful reconciliation. ORACLE's unsigned fatality entry conflicts with Yara's clinical assessment; the Chronicle confirms Wu Yan alive at the sealed research-lab entry at **03:42:17Z on 21 September 2026**. His *ultimate fate is unconfirmed*. The local evidence time and exact case finding remain reviewable story details, not a team-approved final outcome.
- **Hard continuation:** reused medbay export credentials access `/api/failsafe/config`; combining the panel from that config with the Chronicle's safe local mode yields a distinct synthetic evidence flag. It simulates an incident finding, not host privilege or a real kill switch. Mitigation: separate service identities, rotate credentials and require independent authorization for safety controls.
- **Safety:** demo credentials and flags are synthetic. Compose publishes loopback only; container is non-root, read-only, drops capabilities and has no host devices or Docker socket. Default demonstration flags are in server code (never served as source over HTTP); a real assessment deployment can override `MEDBAY_MID_FLAG` and `MEDBAY_HARD_FLAG` with secrets at launch. No claims of a live host privilege escalation or an advanced cryptographic challenge are made.
- **Acceptance:** `tests/test_medbay.py` exercises the full HTTP stage including unauthorized reads/recovery, grant IDOR, wrong/valid and one-time recovery, roster-password rejection, officer-only binary/records, decoy rejection, `strings` non-disclosure, both flags, wrong answers, and process-restart reset. `tests/test_live.py` exercises the actual running Docker container and its compiled ELF. The old Critical combined test still has a *pre-existing unrelated crypto fixture expectation mismatch*; verify its RE-03 part separately rather than calling that suite green. The [maintainer solution](docs/sample_solution.md) is not shipped in the player image.

## Integration boundary

The RE-03 C source has **one authoritative copy here**. The legacy Critical `build_remaining_d.sh` still builds that source into its historical `artifact3_binary` output so existing offline tests can run; that is not a second challenge implementation. The manifest points RE-03 here. `infra/compose.yml` and the separate `dev-test` station UI are not automatically rewired: the final campaign needs an approved upstream foothold → officer identity/session interface (or a reviewed proxy/adaptor into this service), the agreed foothold (`station_crew` or `controlsvc`), a reviewed story flag contract, and the team's agreed RE allocation. The Callisto location, incident cause, final crew fates and proposed roster passwords are **not** set by this Medbay implementation. The supplied crew/station canon remains the single source of truth; do not copy its credential table into this lab. Do not merge to `main` without another team member's approval.
